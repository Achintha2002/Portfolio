Project Overview

TableFlow is an omnichannel restaurant operations ecosystem that unifies guest dining experiences with back-of-house hospitality management. It solves critical inefficiencies in traditional dining—such as crowded waiting areas, manual table turnover delays, fragmented POS billing, and reservation booking conflicts—by synchronizing customer mobile apps, cashier POS terminals, kitchen display systems (KDS), and administrative dashboards in sub-second real time.

Capabilities

Key Features & Core Functionalities

Table QR Check-In & Dining Tabs

Guests scan tabletop QR codes via the mobile client to instantly bind sessions to physical tables, place kitchen-directed orders, dispatch waiter calls, and view live order tallies with zero physical menus.

Live Waitlist & Dynamic Queue

Allows guests to join virtual queues remotely. Dynamically computes wait estimates based on party size, tracks queue positions in real time, and sends automated table-ready push alerts with instant seat allocation.

Intelligent Reservation Engine

Conflict-free scheduler configured with weekly operating windows, customizable order cutoff buffers, and automated holiday date lockouts with zero double-booking vulnerabilities.

Cashier POS & Billing Terminal

Enables managers and cashiers to monitor live table tabs, apply percentage or flat vouchers, settle payments across Cash, Card, and Digital methods, and generate audit-trailed itemized receipts.

Kitchen Display System (KDS)

Station screens receive orders in real time governed by atomic state machines: pending → cooking → ready → served, streaming updates instantaneously to guest screens.

Operating Hours & Broadcasts

Features luxury time pickers, 1-click emergency "Close Today" toggles with automatic timezone-derived midnight resets, and automated multi-channel FCM push notifications for scheduled holidays.

System Blueprint

Technical Architecture & Data Flow

1. Client Tier

Flutter Mobile Client (Guests/Dine-In) & Next.js 16 App Router (Admin/Cashier POS). Decoupled UI with GoRouter and custom luxury design tokens.

2. Application & Push Tier

Node.js / Express Backend. Manages POS billing, emergency conflict engines, Multer file pipelines, and FCM push broadcast dispatchers.

3. Real-Time Data Hub

Supabase PostgreSQL 15+ with Change Data Capture (CDC), WebSocket Broadcast Channels, Row-Level Security (RLS), and temporal validation triggers.

Row-Level Security (RLS) Without Policy Recursion:

Enforced via security definer PostgreSQL functions (get_my_role()) evaluating roles (admin, manager, cashier, kitchen, customer) cleanly without recursive policy locks.

Provider MVVM Service-Repository Pattern:

Mobile features strictly decouple presentation views from state stores (CartProvider) and service repositories (OperatingHoursService, SupabaseService).

Component-Driven Next.js App Router:

Modular boutique luxury UI tokens (LuxuryTimePicker, AuthGuard, Topbar, Sidebar) paired with Recharts analytics.

Relational Schemas & Atomic Integrity:

Strict foreign key cascades, unique table constraints, and transactional rollback guarantees across distributed payments and kitchen stations.

Engineering Rigor

Engineering Complexities & Solutions

01 Real-Time State Synchronization

Dual-Layer Real-Time Synchronization & Resilient Fallbacks

The Challenge

When restaurant opening hours, holiday closures, or table statuses change in the admin console, all connected customer apps and waitlist monitors must update instantly without manual reloads. Relying exclusively on standard polling wastes mobile battery and bandwidth, while pure WebSockets risk connection drops on unstable cellular networks.

The Engineering Solution

Engineered a dual-layer sync architecture combining Supabase Realtime Postgres CDC (Change Data Capture) and Custom WebSocket Broadcast Channels (restaurant_operating_hours_sync). When an admin modifies configurations, the backend emits broadcast events while Postgres replicates the row mutation. The mobile app implements a reactive listener that triggers instant UI updates, supplemented by a 3-second heartbeat auto-polling fallback to guarantee zero stale states across backgrounding and cellular transitions.

02 Concurrency & Conflict Resolution

Concurrency-Safe Reservation Conflict Resolution & Automatic Cancellations

The Challenge

When restaurant management schedules an unscheduled closure or emergency maintenance day, dozens of existing guest reservations may already be confirmed for that date. Canceling these manually or leaving them active leads to severe guest dissatisfaction and operational errors.

The Engineering Solution

Developed an automated conflict resolution pipeline in the backend and database. Upon submitting a closure date, the system executes an atomic transaction querying all overlapping reservations, tallies the conflict count, and presents an actionable resolution modal. Once confirmed, the system auto-cancels conflicting bookings, frees allocated tables, logs cancellation audit records, and broadcasts automated push notification announcements to affected customers in a single coordinated workflow.

03 Database-Level Data Integrity

Database-Level Temporal Validation Triggers for Strict Operating Bounds

The Challenge

Web and mobile frontend validations can easily be bypassed by latent network requests, spoofed API calls, or race conditions during peak rush hours, potentially allowing table reservations outside operating hours or waitlist entries on closed dates.

The Engineering Solution

Implemented server-side PL/pgSQL database triggers (trg_validate_reservation_hours on reservations and trg_validate_queue_hours on queue_entries). These triggers dynamically evaluate input timestamps against restaurant_operating_hours and restaurant_special_closures converted strictly to the local restaurant timezone (Asia/Colombo). If a booking falls outside allowable windows, the database immediately raises a PostgreSQL exception, completely preventing invalid inserts regardless of which client initiated the mutation.
